# Как сделать, чтобы заявки приходили в Телеграм сами

Чтобы заявка приходила **сама, без всяких нажатий**, её отправляет GitHub.
Настраивается один раз, примерно за 20 минут, и бесплатно навсегда.

```
человек заполнил форму
        ↓
   api.github.com          (из России работает, в отличие от Cloudflare)
        ↓
   GitHub Actions          (стоит вне России — поэтому видит Телеграм)
        ↓
   твой Телеграм
```

---

## Что изменилось и почему

Раньше заявку принимал маленький сервер на **Cloudflare Worker**. Он был
правильный, но в России его адрес `*.workers.dev` **заблокирован**, поэтому
форма работала только с VPN.

Отправлять заявку из браузера напрямую в Телеграм (`api.telegram.org`) тоже
нельзя — там блокировка по имени сайта прямо внутри шифрованного соединения.
Сам мессенджер при этом работает: у приложения Телеграма свой способ связи,
он блокировку обходит.

GitHub из России работает, а его серверы стоят вне России. Поэтому заявку
теперь отправляет он.

---

## Из чего состоит отправка

| Что | Где лежит | Кто настраивает |
|---|---|---|
| Токен бота `@SmartFixikBot` | секреты репозитория на GitHub | шаг 1 |
| Твой `chat_id` | секреты репозитория на GitHub | шаг 1 |
| Разрешение запускать workflow | `js/lead-config.js` | шаг 2 |
| Сам текст заявки в Телеграм | `.github/workflows/lead.yml` | уже готов |

**Токен бота на GitHub в секретах** — в код сайта он не попадает и в браузер
клиента тоже. Если он окажется в открытом репозитории, кто угодно сможет
писать от имени бота. Если такое случится — в @BotFather команда `/revoke`
меняет токен на новый.

---

## Шаг 1. Секреты в GitHub

Зайди в репозиторий на GitHub → **Settings** → **Secrets and variables** →
**Actions** → **New repository secret**. Добавь два секрета:

| Name | Secret |
|---|---|
| `BOT_TOKEN` | токен бота (из @BotFather: `/mybots` → твой бот → API Token) |
| `CHAT_ID` | твоё число chat_id |

Оба имени — **ровно большими буквами**, иначе workflow их не найдёт.

### Если chat_id не сохранился

Раньше его показывала страница `/setup` у воркера, но воркер теперь
заблокирован. Теперь для этого есть отдельная задача:

1. Открой своего бота в Телеграме и напиши ему что угодно, хоть «привет» —
   **бот не может написать первым**, так устроен Телеграм.
2. В репозитории: вкладка **Actions** → слева **«Узнать chat_id»** →
   справа **Run workflow** → **Run workflow**.
3. Через полминуты открой запуск и найди в журнале строку
   `твой chat_id: 987654321`. Это число и нужно.

---

## Шаг 2. Разрешение для сайта (токен GitHub)

Чтобы сайт мог запускать workflow, ему нужен отдельный токен. Он будет
лежать открыто в `js/lead-config.js` — так и задумано, и ниже написано,
почему это не опасно.

1. GitHub → своя аватарка → **Settings** → внизу **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. Заполни:
   - **Token name**: `smartfix-zayavki`
   - **Expiration**: поставь подальше, например на год. Когда истечёт,
     форма перестанет отправлять сама и покажет кнопку в Телеграм —
     надо будет сделать новый токен и вписать сюда же.
   - **Repository access**: `Only select repositories` → выбери
     **mysiteSmartFix**. Больше никакие репозитории ему не видны.
3. Раскрой **Repository permissions** и поставь **только одно** разрешение:

   | Разрешение | Значение |
   |---|---|
   | **Actions** | **Read and write** |

   Всё остальное оставь как есть — `No access`. Токену не нужны ни код,
   ни секреты, ни настройки.

4. **Generate token** → скопируй строку, начинается на `github_pat_`.
5. Впиши её в файл `js/lead-config.js` в строку `token:`:

   ```js
   token: 'github_pat_11ABCDEFG...',
   ```

**GitHub предупредит, что в файле найден секрет** — это ожидаемо, ведь токен
тут и должен лежать открыто, он умеет только запускать workflow в этом
репозитории. Нажми **Allow secret** / «Разрешить». А вот **токен бота** сюда
не вписывай никогда: он живёт только в секретах репозитория.

---

## Шаг 3. Проверить

1. В репозитории: вкладка **Actions** → слева **«Заявка с сайта»** →
   **Run workflow**.
2. В поле `payload` вставь:

   ```json
   {"name": "Проверка", "phone": "+7 961 999-76-81"}
   ```

3. Нажми **Run workflow**. Через полминуты в Телеграм должно прийти
   сообщение от `@SmartFixikBot`:

   > 🔔 **Новая заявка с сайта**
   >
   > **Имя:** Проверка
   > **Телефон:** +7 961 999-76-81

4. Теперь открой сайт, заполни форму и нажми «Отправить заявку».
   Должно появиться «Заявка отправлена», а в Телеграм прийти сообщение
   **через 15–30 секунд**. Так и задумано: браузер только ставит задачу
   в очередь, а отправляет её GitHub — на это нужно несколько секунд.
   Для записи на ремонт это неважно.

## Запасной путь: кнопка в Телеграм

Если автоматика не сработала — например, GitHub недоступен, токен отозван
или истёк, — форма не молчит и не теряет заявку. Она показывает кнопку:

> Отправить автоматически не получилось. Нажми кнопку — откроется Телеграм
> с уже готовой заявкой, останется нажать «Отправить».
>
> **[ Открыть Телеграм с заявкой ]**
>
> Или позвони: +7 (961) 999-76-81

Человек нажимает кнопку, у него открывается чат с тобой, где текст заявки
уже подставлен. Остаётся нажать «Отправить». Этот способ работает всегда,
ничего не требует и не зависит ни от GitHub, ни от блокировок.

Ник для этой кнопки — в том же `js/lead-config.js`, строка `telegram`.

## Если не работает

| Что видно | Что делать |
|---|---|
| Заявка на сайте уходит, кнопки в Телеграм нет, но сообщение не приходит | Открой **Actions** и посмотри последний запуск «Заявка с сайта». Он красный — там написана причина. Чаще всего не заданы или перепутаны секреты из шага 1 (проверь, что имена большими буквами) |
| Форма сразу показывает кнопку в Телеграм | Не вписан токен в `js/lead-config.js` (шаг 2), либо он отозван или истёк |
| В журнале `Unauthorized` | Ошибка в `BOT_TOKEN` — возьми токен заново в @BotFather |
| В журнале `chat not found` | Неверный `CHAT_ID`, либо ты ни разу не написал боту |
| В журнале `До Телеграма не достучались` | У Телеграма временные неполадки — попробуй ещё раз через час |
| Раньше работало, теперь нет | Посмотри, не истёк ли год у токена GitHub (шаг 2). GitHub пришлёт письмо заранее |

GitHub сам присылает письмо, если запуск workflow упал — так ты узнаешь
о поломке, даже если на неё не смотрел.

## Честно про токен GitHub

Токен лежит открыто в коде сайта, и вот что это значит.

**Чего он не может:** читать твой код, менять его, видеть секреты репозитория,
заходить в другие репозитории. Ему выдано ровно одно разрешение — «Actions:
Read and write» в одном репозитории.

**Что он может:** запускать workflow. То есть в худшем случае кто-то
развлечения ради нашлёт тебе лишних сообщений в Телеграм. Настоящие заявки
это не затрагивает, код сайта тоже.

**Если надоело** — удали токен на GitHub (Settings → Developer settings →
Personal access tokens), создай новый и впиши в `js/lead-config.js`. Пока
вписываешь, форма работает через кнопку в Телеграм. Токен бота при этом
не меняется и никуда не девается.

## Лимит заявок и спам

Ловушка для ботов (невидимое поле в форме) работает как раньше: заполнил
её — заявка молча не отправляется, а робот думает, что всё прошло.

А вот **настоящего замка «3 заявки в сутки с одного адреса» больше нет**.
Он был на сервере Cloudflare, которого теперь нет; GitHub Actions так
считать не умеет — у него нет памяти между запусками. Осталась только
подсказка в браузере: после трёх отправок форма скажет «на сегодня хватит».
Человек в режиме инкогнито её обойдёт.

Для мастерской это, скорее всего, неважно. Если спам начнётся — напиши,
придумаем: можно считать заявки в самом репозитории или поставить
ограничение на триггер.

---

## Что делать со старым воркером

Файл `worker-telegram.js` и воркер на Cloudflare больше не нужны — сайт
к нему не обращается. Удалять не обязательно: он просто лежит и ничего
не делает.

Если надумаешь удалить — сначала убедись, что новая схема работает
(шаг 3), и заранее сохрани из воркера **токен бота и chat_id**: они там
лежат в переменных, и если удалить воркер, посмотреть их будет больше негде.
