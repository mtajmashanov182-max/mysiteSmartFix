# Как сделать, чтобы заявки приходили в Телеграм сами

Чтобы заявка приходила **сама, без всяких нажатий**, нужен маленький сервер.
Он бесплатный и настраивается один раз примерно за 15 минут.

Схема простая:

```
человек заполнил форму  →  сервер Cloudflare  →  твой Телеграм
                              (здесь спрятан
                               токен бота)
```

Токен бота нельзя держать в коде сайта — его увидел бы любой, кто откроет
исходник страницы. Поэтому он лежит на сервере, в коде сайта его нет.

---

## Важно про твою сеть

На твоём интернете **api.telegram.org заблокирован** — проверено, соединение
обрывается, хотя сам Телеграм работает. Поэтому:

- команды вида «открой в браузере `api.telegram.org/...`» **у тебя не сработают**,
  их тут нет;
- всё, что нужно узнать у Телеграма, будет узнавать **сервер** — он стоит
  на Cloudflare, вне блокировки, и до Телеграма дотягивается свободно.

---

## Шаг 1. Бот в Телеграме — ✅ уже сделано

Бот `@SmartFixikBot` создан, токен получен. **Токен никому не показывай** —
это ключ от бота. В файлы сайта его не вписывай и на GitHub не выкладывай:
если он попадёт в публичный репозиторий, кто угодно сможет писать от имени
твоего бота. Если такое случится — в @BotFather команда `/revoke` меняет
токен на новый.

## Шаг 2. Напиши боту сообщение

Открой `@SmartFixikBot` в Телеграме и напиши ему что угодно, хоть «привет».

Это обязательно: **бот не может написать первым** — так устроен Телеграм.
Пока ты ему не написал, он не сможет прислать тебе ни одной заявки.

## Шаг 3. Создать сервер на Cloudflare

1. Зайди на **dash.cloudflare.com** и зарегистрируйся (бесплатно, карта не нужна).
2. Слева выбери **Workers & Pages** → **Create** → **Worker**.
3. Дай имя, например `smartfix-zayavki` → **Deploy**.
4. Нажми **Edit code**, удали то, что там написано, и вставь целиком
   содержимое файла **`worker-telegram.js`** из этой папки.
5. **Deploy**.
6. Зайди в **Settings** → **Variables and Secrets** и добавь переменную:

   | Имя | Значение | Тип |
   |---|---|---|
   | `BOT_TOKEN` | токен бота | **Secret** |

7. **Save and Deploy**.
8. Скопируй адрес воркера — он показан сверху, вида
   `https://smartfix-zayavki.твоё-имя.workers.dev`

## Шаг 4. Узнать свой chat_id через сервер

Открой в браузере адрес воркера, добавив в конце `/setup`:

```
https://smartfix-zayavki.твоё-имя.workers.dev/setup
```

Сервер сходит в Телеграм и покажет ответ примерно такой:

```json
{
  "ok": true,
  "твой chat_id": 987654321,
  "кто писал боту": [ { "chat_id": 987654321, "имя": "Сайд", "username": "@saidbro335" } ],
  "что дальше": "впиши chat_id в переменную CHAT_ID в настройках воркера..."
}
```

Число из строки `твой chat_id` — это то, что нужно.

Если вместо этого ответ `"боту ещё никто не писал"` — значит не сделан шаг 2.

## Шаг 5. Добавить chat_id в настройки

В том же разделе **Settings** → **Variables and Secrets** добавь вторую
переменную:

| Имя | Значение | Тип |
|---|---|---|
| `CHAT_ID` | число из шага 4 | Text |

**Save and Deploy**.

## Шаг 6. Проверить связь, ещё не трогая сайт

Прежде чем возиться с сайтом, убедись, что сервер и Телеграм друг друга видят.
Открой в браузере адрес воркера, дописав в конце `/test?key=` и **последние
8 символов токена бота**:

```
https://твой-воркер.workers.dev/test?key=NUDUAuqU
```

Ключ нужен, чтобы кто попало не мог слать тебе сообщения. Последние 8 символов
своего токена смотри в @BotFather (команда `/mybots` → твой бот → API Token).

Если всё в порядке, ответ будет `{"ok": true, "готово": "сообщение отправлено..."}`,
а тебе в Телеграм придёт:

> 🔔 **Проверка связи**
>
> Это пробное сообщение с сервера. Если ты его видишь — заявки с сайта тоже дойдут.

**Не пришло?** Значит проблема на этом участке, и до сайта дело ещё не дошло.
Ответ сервера подскажет, что именно:

| Ответ | Что делать |
|---|---|
| `нужен ключ в адресе` | Ошибся в ключе, проверь последние 8 символов токена |
| `Телеграм отказал: chat not found` | Неверный `CHAT_ID` или не сделан шаг 2 |
| `Телеграм отказал: Unauthorized` | Ошибка в `BOT_TOKEN` |

## Шаг 7. Прописать адрес сервера на сайте

В файле `booking.html` найди строку:

```html
<form class="js-form" id="booking-form" data-whatsapp="79619997681" data-endpoint="" novalidate>
```

и впиши адрес воркера в пустые кавычки:

```html
data-endpoint="https://smartfix-zayavki.твоё-имя.workers.dev"
```

## Шаг 8. Разрешить своему сайту отправлять заявки

В файле `worker-telegram.js` в самом начале есть список `ALLOWED_ORIGINS`.
Впиши туда адреса своего сайта:

```js
const ALLOWED_ORIGINS = [
  'null',
  'https://твой-домен.ру',            // ← сюда свой домен
  'https://твой-ник.github.io',       // ← и GitHub Pages, если есть
];
```

Потом вернись на Cloudflare, открой код воркера, замени содержимое
на новую версию и нажми **Deploy**. Без этого шага сервер будет отвечать
«заявки с этого адреса не принимаю».

## Шаг 9. Включить лимит заявок (чтобы не спамили)

Сейчас никто не мешает отправить форму сто раз подряд. Лимит — **3 заявки
в сутки с одного адреса** — включается отдельно: серверу нужно место, где
запоминать, кто сколько уже отправил.

1. В Cloudflare слева открой **Storage & Databases** → **KV**
   (в новом интерфейсе: **Storage** → **KV**).
2. **Create a namespace** (или **Create instance**), имя `smartfix-leads` → создать.
3. Вернись к своему воркеру → **Settings** → **Bindings** → **Add** →
   выбери **KV namespace**.
4. Заполни:
   - Variable name: `LEADS`  (ровно так, большими буквами)
   - KV namespace: `smartfix-leads`
5. **Deploy**.

**Проверь, что включилось:** открой адрес воркера с `/setup`. В ответе будет
строка:

```json
"лимит заявок": "включён: 3 заявки в сутки с одного адреса"
```

Если там написано `НЕ ВКЛЮЧЁН` — значит база не привязалась, вернись к шагу 3.

**Важно:** пока база не подключена, лимит **молча не работает**, а заявки
принимаются как обычно. Так сделано нарочно — чтобы сайт не сломался, если
про этот шаг забыть. Но и спам тогда не остановится.

### Почему лимит на сервере, а не в браузере

Проверка в браузере обходится за пять секунд: открыл страницу в режиме
инкогнито — и счётчик пустой. Поэтому настоящий замок стоит на сервере,
а в браузере — только подсказка, чтобы человек не ждал ответа зря.

### Одна честная оговорка

Счёт идёт по адресу посетителя в интернете. У мобильных операторов
и в офисных сетях один и тот же адрес часто делят десятки людей —
это называется NAT. Значит, теоретически трое разных клиентов,
сидящих через один мобильный интернет, могут занять лимит друг друга.
Для мастерской это редкость, но знать стоит. Если станет мешать —
лимит можно поднять или сделать другим способом.

## Как проверить

Открой сайт, заполни форму, нажми кнопку. Должно появиться
«Заявка отправлена», а в Телеграм — сообщение от `@SmartFixikBot`:

> 🔔 **Новая заявка с сайта**
>
> **Имя:** Сайд
> **Телефон:** +7 961 999-76-81
> ...

## Если не работает

Открой адрес воркера в браузере. Он ответит одним из сообщений — по нему
понятно, что не так:

| Что ответил | Что делать |
|---|---|
| `принимаю только POST` | Всё хорошо, сервер работает. Проблема не в нём |
| `заявки с этого адреса не принимаю` | Не сделан шаг 8 — домен не вписан в `ALLOWED_ORIGINS` |
| `сначала добавь BOT_TOKEN` | Не сделан шаг 3.6 |
| `Телеграм отказал: chat not found` | Неверный `CHAT_ID` или не сделан шаг 2 |
| `Телеграм отказал: Unauthorized` | Ошибка в `BOT_TOKEN` |
| `боту ещё никто не писал` | Не сделан шаг 2 |

Ещё можно посмотреть, что происходит, в самом Cloudflare:
**Worker → Logs → Begin log stream**, потом отправить заявку с сайта.

Если **сам адрес воркера не открывается** — возможно, твой провайдер
блокирует и `workers.dev`. Тогда напиши мне, придумаем обход: можно
привязать воркер к своему домену, и он заработает через обычный адрес.

## Если сервер настроить не вышло

Ничего страшного: пока `data-endpoint` пустой (или сервер не ответил),
сайт сам переходит на запасной путь — открывает WhatsApp с готовым текстом.
То есть заявки не теряются при любом раскладе.

## После настройки

Блок с `/setup` в `worker-telegram.js` можно удалить — он нужен был один
раз. Правда, вреда от него нет: `chat_id` без токена бота ничего не даёт.
